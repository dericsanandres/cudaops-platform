# v0.2.0 release notes

Version 0.2.0 is the first Kubernetes-oriented portfolio release of CUDAOps. It preserves the accepted local CUDA and CPU processing behavior while adding deployment, monitoring, delivery, and operational foundations.

## Highlights

- Deploy the API, worker, Redis, and shared job storage through Helm.
- Request a GPU on compute-capability-12 nodes by default, with a CPU-only values override.
- Integrate with an existing Prometheus Operator through opt-in ServiceMonitors and release-scoped alert rules.
- Document Kubernetes prerequisites, worker failure recovery, and initial service objectives.
- Validate Go, CPU processor, containers, and Helm charts in GitHub Actions.
- Scan Go code with CodeQL and publish separate API and worker images to GHCR from `v*` tags.

## Container images

Creating the `v0.2.0` tag publishes these image repositories with semantic-version and commit-SHA tags:

- `ghcr.io/dericsanandres/cudaops-platform-api`
- `ghcr.io/dericsanandres/cudaops-platform-worker`

The Helm chart defaults both image tags to its `appVersion`, `0.2.0`. The tag workflow completed successfully, and both image manifests are publicly readable from GHCR.

## Deployment requirements

- Kubernetes with an RWX storage class or existing RWX claim.
- Immutable API and worker images accessible from the cluster.
- For GPU mode, an NVIDIA device plugin or GPU Operator and a node labeled `nvidia.com/gpu.compute.major=12`.
- For bundled monitoring resources, an existing Prometheus Operator installation with matching selectors.

The chart does not install cluster-level GPU or monitoring operators. Preserve the Windows NVIDIA display-driver boundary when using the documented WSL environment.

- CodeQL passed the delivery pull request and pre-release baseline commit `a5d7734`.

Live Kubernetes deployment, Prometheus alert routing, and runtime image pulls remain release-acceptance checks rather than completed claims.

## Current limitations

One worker processes one image at a time. There is no authentication, cancellation, retention policy, web UI, distributed tracing, or remote GPU CI. Terraform, cluster-managed GPU telemetry, production Redis, and additional image operations remain deferred.
